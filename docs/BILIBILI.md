## 弹幕接收器

采用 [blivedm](https://github.com/xfgryujk/blivedm)，也是 [Open-LLM-VTuber 直播接入](https://docs.llmvtuber.com/en/docs/user-guide/live/bilibili/) 使用的库。网页端路线通过房间号建立弹幕 WebSocket，不以开发者 AppId/主播身份码为先决条件；官方开放平台路线仍是另一种选择。匿名用户名可能被打码，平台接口可变化，不能保证所有时间、网络和房间都免登录可用。

可选依赖固定到已检查的上游提交，不使用 PyPI 上同名的其他包：

```powershell
uv pip install --python .venv/Scripts/python.exe -r requirements-bilibili.txt
```

接到已启动的本地小征（将房间号替换成自己的）：

```powershell
.\.venv\Scripts\python.exe -m companion.bilibili --room <房间号> --target http://127.0.0.1:17870
```

单独运行接收器前，需要播音控制端在线且后端处于 live 场景；`启动直播.ps1` 包含切换 live 的启动步骤。接收器本身不切换场景，不推流或发送 B 站聊天。`--listen-only --seconds 55` 只接收不转发；省略 seconds 则持续运行到停止。网页读取固定的 `artifacts/runtime-bilibili/status.json`；`--report` 的自定义路径用于独立探针，不能指望网页读取其他文件。

- 上游处理网页鉴权、30 秒心跳、压缩包解析和长连接重连；本地补 2–30 秒重连退避、初始化失败重试以及状态记录。实测主动关闭 WebSocket 时上游可能卡在等待；监督循环额外检测 closed 状态和 65 秒无心跳，重建连接，避免显示假在线。
- 回调只写有界队列，网络接收不等待 LLM/TTS。100 条队列、15 秒本地等待期限；同一事件按房间/时间/随机数/发送人/内容摘要去重，不合并不同观众的同文弹幕。
- 只在目标小征处于 live 场景时 POST `/api/live/messages`，沿用现有候选池和公开输入处理。私聊时丢弃，不自动切换；超时的 POST 不盲重试，避免重复回应。
- 可读取进程环境变量 `BILIBILI_SESSDATA` 作为可选本机登录态，但匿名验证不使用它。不抓取浏览器密码/Cookie，不输出认证令牌，不将凭据存入网页或报告。
- 当前仅转发本房间普通弹幕；礼物、舰长、付费留言和跨房镜像弹幕未接入回应。

验证入口：`tests/test_bilibili.py`（配合 `tests/test_inbox.py`），以及 `python probes/bilibili_live.py --room <房间号>`。后者只读 B 站，在独立的 17872 本地实例中使用真实 LLM/SAPI 和 Live2D，需要全局 Python 中的 Playwright；会消耗模型请求，不对外发弹幕/开播。实际结果见 `artifacts/bilibili-live-check.json`，不可把本地验收当成主人房间已上线。
