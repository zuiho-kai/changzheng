# Local Live2D implementation

Goal: switch the local pet and stream overlay to Hiyori, with actual playback-driven mouth movement and immediate interruption.

Architecture: keep the existing controller/observer separation. A local iframe renders the licensed model using Pixi 6 and Cubism 4. The controller samples RMS at the estimated device output cursor. Only the current turn can publish a mouth value; only live observers receive it. Renderers close the mouth after 250 ms without updates. No microphone, audio duplication, or private text enters the renderer.

Alternatives considered: native LiveHime avatar integration currently blocked by UI control; separate VTuber app would duplicate state and audio. Reuse the existing web overlay for this increment.

Steps:
1. Vendor only browser runtime distributions and the existing local sample, retaining notices. No npm publishing tools at runtime.
2. Add a preset selector, iframe renderer and public avatar update event.
3. Send playback-position RMS values with current-turn validation; clear on Stop, finish and disconnect.
4. Verify a real rendered model and real TTS playback in an isolated backend. Test private/live observer separation and invalid values. Keep main daily data intact.
